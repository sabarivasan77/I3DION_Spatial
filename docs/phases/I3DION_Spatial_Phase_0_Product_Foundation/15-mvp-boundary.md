# I3DION Spatial --- MVP Boundary

**Document ID:** PS-MVP-001\
**Version:** 0.2\
**Status:** Draft / Scope-control document

## 1. MVP Objective

The MVP exists to prove that I3DION Spatial can create a useful
end-to-end industrial product visualization and sales workflow.

## 2. MVP Success Loop

**Company → Product → Assets → Catalog/Experience → QR/Link → Customer →
3D → AR → Sales CTA → Lead**

If this loop does not work reliably, additional advanced features should
not be prioritized over fixing the core loop.

## 3. IN SCOPE

### A. Organization/Company Foundation

-   Company identity/profile
-   Branding information
-   Required organization administration

### B. Product Management

-   Create/edit products
-   Product descriptions
-   Specifications
-   Images/media
-   Supported 3D model asset

### C. Catalog

-   Create catalog
-   Select products
-   Arrange products
-   Preview
-   Publish

### D. QR

-   Generate QR for supported experiences
-   Download/share QR
-   Resolve QR to intended experience

### E. Customer Product Experience

-   Product information
-   Specifications
-   Media
-   Documents where supported

### F. Interactive 3D

-   Load model
-   Rotate
-   Zoom
-   Inspect

### G. AR

-   Launch AR
-   Place product
-   Move
-   Rotate
-   Scale
-   Lock/unlock
-   Reset

### H. Demonstration

-   Animation playback where supported by the asset/runtime

### I. Sales

-   Request quote
-   Contact sales
-   Inquiry/lead capture

## 4. OUT OF SCOPE FOR MVP

Unless a separate decision is approved: - Full CAD authoring -
Engineering simulation - Full ERP - Full CRM - Generic social
networking - Advanced AI assistant - Complex AI recommendations -
Advanced predictive analytics - Enterprise collaboration suite - Highly
advanced product configurator - Open public model-upload marketplace -
Any feature that does not support the validated core journey

## 5. MVP Quality Bar

A feature is not MVP-complete merely because the UI exists.

Each in-scope capability requires: - Product requirement - UX flow - UI
specification - Technical implementation - Validation -
Error/empty/loading states - Security review where applicable -
Accessibility consideration - Automated/manual testing as appropriate -
Documentation - GitHub issue/PR traceability

## 6. MVP Exit Criteria

Before calling MVP complete: 1. Core user journey works end-to-end. 2.
Critical and blocker defects are resolved. 3. Supported browsers/devices
are verified. 4. Product asset workflow is reliable. 5. QR experience
works. 6. 3D experience works. 7. AR experience works on the supported
target environment. 8. Lead/inquiry flow works. 9. Analytics/events
required for MVP are captured. 10. Deployment and rollback procedures
exist. 11. Security checks are completed. 12. Pilot users can complete
the primary workflow.

## 7. Scope Change Rule

Any new feature must be evaluated against: **User problem + Evidence +
Business value + Strategic fit + Effort + Risk + Opportunity cost.**

## 8. MVP vs Version 1.0

"MVP" means the smallest product capable of validating the core value
loop. "Version 1.0" may contain additional hardening and validated
capabilities. The terms must not be treated as synonyms without an
explicit release definition.
